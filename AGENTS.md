# Agent instructions

These instructions apply to the entire repository. Read [AI-CONTEXT.md](AI-CONTEXT.md) before making a substantive change; it describes the architecture, data flow, and generated-code boundaries.

## Working rules

- Use `pnpm`. The Docker image and CI use pnpm 9.15.0; the project requires Node.js 20 or newer.
- Inspect the surrounding pallet, handler, schema, and model code before changing behavior. Similar event processors often encode compatibility rules that should remain consistent.
- Keep changes scoped. Do not reformat unrelated files or overwrite existing worktree changes.
- Use the `~/*` alias for imports from `src/*` and follow the existing TypeScript style: four spaces, single quotes, no semicolons, 120-column lines.
- Treat blockchain identifiers, balances, token IDs, collection IDs, and block numbers carefully. Preserve the repository's existing `bigint`/string conversions; do not introduce lossy `number` conversions.
- Never commit secrets or copy values from `.env`. Add documented placeholders to `.env.example` when introducing configuration.

## Generated and source-of-truth files

- `schema.graphql` is the source of truth for persisted entities. `src/model/generated/` is generated by `pnpm run schema:codegen`; do not hand-edit it.
- `typegen/*.jsonl` is chain metadata and `src/type/` is generated runtime type data. Regenerate it with the metadata scripts; do not patch generated runtime versions manually.
- `lib/` is build output and must not be edited or committed.
- `db/migrations/` contains migration artifacts. Generate schema migrations with `pnpm run db:generate`, then inspect the generated SQL/JavaScript carefully before applying or committing it.
- Hand-written model substitutions belong in `src/model/overridden/` and must be re-exported from `src/model/index.ts` when needed.

## Change workflows

When adding or changing an indexed event or call:

1. Confirm the event/call exists in `src/type/events`, `src/type/calls`, or regenerated metadata output.
2. Update subscriptions in `src/processor.config.ts` if it is not already included through its pallet group.
3. Add or update the pallet processor under `src/pallet/<pallet>/`.
4. Wire the handler in `src/processor.handler.ts`.
5. Update `schema.graphql` when persistence changes, regenerate models, and add a migration.
6. Consider both Matrixchain and Relaychain behavior. Network selection is based on `CHAIN_NAME` through `isRelay()`/`isMainnet()`.
7. Preserve failed-extrinsic behavior: failed calls may be indexed for metadata, but their state-changing call processors must not run.

When changing queue work:

- Keep queue declarations in `src/queue/`, job payload logic in `src/worker/jobs/`, and dispatch/processing behavior in `src/worker/processors/`.
- Assume multiple worker replicas may exist. Do not globally clean active BullMQ jobs or locks during startup.
- Keep jobs retry-safe and idempotent where practical.

When changing GraphQL behavior:

- Persisted schema changes start in `schema.graphql`.
- Custom queries and mutations live in `src/server-extension/` and are exported from both `src/server-extension/index.ts` and `src/server-extension/resolvers/index.ts` as required.
- Validate inputs and parameterize database queries. Preserve the existing SSRF protections for metadata or user-provided URLs.

## Validation

Run the smallest relevant checks, then broaden them for cross-cutting changes:

```bash
pnpm run ci:lint
pnpm run ci:prettier
pnpm run build
```

Notes:

- `pnpm run lint` and `pnpm run prettier` modify files; use the `ci:*` variants for read-only checks.
- There is currently no automated unit-test script. For processor, migration, or queue changes, describe the manual or integration verification performed.
- Schema changes additionally require `pnpm run schema:codegen` and migration review.
- Metadata/runtime upgrades additionally require `pnpm run metadata:typegen` after metadata has been fetched or updated for all supported networks.
- Do not run database wipes, migrations against a shared database, metadata fetches against remote nodes, or other destructive/networked operations without confirming the target and scope.

## Documentation maintenance

Update `AI-CONTEXT.md` when a change alters service topology, primary data flow, source-of-truth locations, generated-code workflows, or standard commands. Keep this file focused on executable agent rules; keep explanatory architecture in `AI-CONTEXT.md`.
